# Creation Example

## Breakdown

- Intent: create a usable artifact.
- Subject: the receiver.
- Path: sees -> understands -> believes -> acts.
- Constraint: attention is limited.
- Acceptance: the receiver can repeat the point and act.

## Decision

Build the artifact around one path.

## Path

- Motive: get a useful answer.
- Interpretation: see the main promise.
- Action: read or use the first section.
- Resistance: abstraction, length, or weak proof.
- Signal: example, result, checklist, or next action.
- State change: doubt becomes clarity.
- Continuation: save, share, use, buy, ask, or decide.

## Evidence

- Confirmed: artifact must be created, receiver is defined.
- User-provided: attention is limited.
- Inference: one clear message beats many weak messages.
- Unconfirmed: whether the receiver already knows the topic.

## Data gaps

- Unknown: receiver's prior knowledge level. If expert, start with the insight. If beginner, start with context.

## Minimum test

- Goal: prove one message.
- Input: one claim and one example.
- Action: produce a short version.
- Output: draft.
- Pass condition: the receiver can repeat the claim.
- Fail signal: the receiver says it is vague.
- Next step: expand only the parts that passed.
- Do not do: add more sections before the first message works.

## Gates

- Path gate: PASS — artifact path defined (sees → understands → believes → acts).
- Evidence gate: HOLD — receiver knowledge level unknown; test with short version first.
- Minimum-test gate: NOT STARTED — short version not yet produced.

## Model check

1. Essence
   Finding: the artifact needs one controlling idea.
   Fix: remove secondary claims.

2. Narrative
   Finding: the receiver needs a reason to continue.
   Fix: start from conflict or consequence.

3. Evidence
   Finding: trust needs proof.
   Fix: add one concrete example.

## Usable result

Create the short version first. Expand after it passes.
