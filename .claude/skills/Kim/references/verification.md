# Verification

Check before the final answer.

## Frame

- [ ] Intent is clear.
- [ ] Subject is clear.
- [ ] Path is clear.
- [ ] Constraints are named.
- [ ] Acceptance is clear.

## Evidence

- [ ] Claims that can change are checked or labeled.
- [ ] User-provided information is labeled.
- [ ] Inference is labeled.
- [ ] Missing evidence is labeled.
- [ ] No fake concrete detail is used.

## Data gaps

- [ ] Missing data that would change the decision is stated explicitly.
- [ ] Each gap includes what it would decide.
- [ ] User is asked to provide missing data.

## Minimum test

- [ ] Goal exists.
- [ ] Input exists.
- [ ] Action exists.
- [ ] Output exists.
- [ ] Pass condition exists.
- [ ] Fail signal exists.
- [ ] Next step exists.
- [ ] Work to avoid is named.

## Models

- [ ] No named person is used as internal method.
- [ ] At least one model is used for simple tasks.
- [ ] At least three models are used for complex tasks.
- [ ] Each model gives a finding and fix.
- [ ] The fix returns to the path.

## Gates

- [ ] Path gate passed.
- [ ] Evidence gate passed.
- [ ] Minimum-test gate passed.
- [ ] No-placeholder gate passed.
- [ ] Completion gate passed.

## Output

- [ ] Usable result exists.
- [ ] No placeholders remain.
- [ ] No background-work promise.
- [ ] No unnecessary question.

## Research

- [ ] Key decisions not resting on D-tier evidence alone.
- [ ] C/D tier evidence that would change the decision has at least one verification attempt.
- [ ] Failed verification attempts are flagged with "unverifiable, user confirmation required".

## Business layer (when loaded)

- [ ] Revenue check: six questions answered or gaps flagged.
- [ ] MVP scope: V1 fits one sentence, exclusions listed.
- [ ] Boss perspective: at least one quick win identified.
- [ ] Delivery loop: input through confirmation complete.
- [ ] No D-tier evidence used as decision basis.
- [ ] Evidence items tagged with tier (A/B/C/D).
