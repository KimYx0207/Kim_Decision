# 校准示例

## 拆解

- 意图：修正已有草稿或方案。
- 主体：接收者。
- 路径：接收 -> 理解 -> 行动 -> 得到信号。
- 约束：接收者不能依赖额外解释。
- 验收：接收者能完成下一步动作。

## 结论

先修第一个路径断点。

## 路径

- 动机：推进事情。
- 理解：看懂承诺。
- 行动：执行一个指令。
- 阻力：表达不清或选择太多。
- 信号：接收者知道动作是否有效。
- 状态变化：困惑变成推进。
- 延续动作：出现下一步。

## 证据

- Confirmed: 草稿存在，接收者存在，路径断点已定位。
- User-provided: 接收者不能依赖额外解释。
- Inference: 表达不清是主要阻碍。
- Unconfirmed: 其他段落是否也有断点。

## 数据缺口

- 未知：有多少段落存在路径断点。如果只有一个，修完就发。如果很多，按影响优先排序。

## 最小验证

- 目标：让一个动作变清楚。
- 输入：当前草稿。
- 动作：把模糊表达换成动作表达。
- 输出：修改后的段落。
- 通过标准：接收者知道下一步做什么。
- 失败信号：接收者问接下来呢。
- 下一步：找一个接收者测试。
- 不做什么：不先重写整个系统。

## 硬门

- Path gate: 通过 — 路径断点已定位。
- Evidence gate: 通过 — 断点在草稿中可见。
- Minimum-test gate: 未开始 — 修改后的段落未与接收者测试。

## 模型校验

1. 路径
   发现：移动停在行动之前。
   修正：把动作提前。

2. 摩擦
   发现：选择负担高。
   修正：只保留一个主动作。

3. 叙事
   发现：承诺难复述。
   修正：压成一句话。

## 可用结果

先改第一个断点，再测试。
