# 排错示例

## 拆解

- 意图：恢复断掉的路径。
- 主体：操作者。
- 路径：运行 -> 失败 -> 检查 -> 测试 -> 通过。
- 约束：避免扩大损坏。
- 验收：同一失败路径通过。

## 结论

先收集证据，再改方案。

## 路径

- 动机：解除阻塞。
- 理解：找到失败步骤。
- 行动：捕捉完整现象。
- 阻力：猜。
- 信号：复现结果。
- 状态变化：现象变成假设。
- 延续动作：最小修复和验证。

## 证据

- Confirmed: 路径已断，现象存在。
- User-provided: 避免扩大损坏。
- Inference: 现象指向一个根因。
- Unconfirmed: 实际根因（现象不是原因）。

## 数据缺口

- 未知：完整复现路径。没有复现，任何修复都是猜测。先捕捉精确步骤再继续。

## 最小验证

- 目标：证明一个根因。
- 输入：完整现象和复现路径。
- 动作：只改一个变量。
- 输出：测试结果。
- 通过标准：失败路径通过。
- 失败信号：原失败仍存在。
- 下一步：保留修复或重构假设。
- 不做什么：不叠加多个改动。

## 硬门

- Path gate: 通过 — 失败→检查→测试→通过路径已定义。
- Evidence gate: 暂缓 — 复现未捕捉；不能直接上修复。
- Minimum-test gate: 未开始 — 复现步骤未写出。

## 模型校验

1. 根因
   发现：现象不是原因。
   修正：先复现。

2. 最小改动
   发现：多项改动会掩盖证据。
   修正：只改一个变量。

3. 完成
   发现：未验证的修复不算完成。
   修正：重跑失败路径。

## 可用结果

写复现步骤，做一个改动，验证同一路径。
