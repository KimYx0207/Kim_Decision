# 输出

## 规则

使用抽象方法。

最终回答可以使用具体证据。

不要编具体细节。

## 事实标签

使用：

```text
已确认
用户给定
我的推断
未确认
```

## 抽象词处理

抽象词必须给可观察标准。

| 词 | 检查标准 |
|---|---|
| AI腔 | 没有主体、数字、例子、动作、通过标准 |
| 不可执行 | 缺执行者、输入、动作、输出、通过标准 |
| 路径弱 | 主体无法从当前状态走到目标状态 |
| 摩擦高 | 选择太多、思考太多、步骤太多、信任成本太高 |
| 质量 | 错误更少、速度更快、转化更高、结构更清楚、成本更低 |
| 闭环 | 输入、动作、输出、信号、下一步 |

## 具体证据

需要增强可信度时，使用真实材料：

```text
人物
公司
产品
来源
日期
数字
案例
命令
路径
文件
```

标注不确定性。

## 结束方式

最后必须给可用结果。

不要只用原则收尾。
